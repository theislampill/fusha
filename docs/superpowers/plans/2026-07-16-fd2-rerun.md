# FD2 Producer-Aware Rerun Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-run the 455 verified rows through the shared compiler with only the calibrated F-B/F-C producers active and deliver a fact-derived FD2 report, verdict matrix, Markdown report, committed-fixture validator, and full-harness pass.

**Architecture:** Extend `tools/fd_compiler.py` with a pure FD2 compilation path that accepts already-decoded source rows, typed producer outputs, and an in-memory merged occurrence index. Keep external path handling in `tools/fd2_rerun.py`, and keep fixture-only validation in `tools/validate_fd2_rerun.py`. Preserve the prior `fd-455-*` contract unchanged.

**Tech Stack:** Python 3 standard library, JSON/JSONL, existing F-A typed-claim validators, existing F-B/F-C producer modules, `unittest`, and `tools/check_regressions.py`.

## Global Constraints

- Apply F-B only to `clitic_pronoun_compositions` rows and retain its producer guards.
- Apply F-C only when `_input_candidate` evidence conditions hold and `build_contract_record` accepts the input.
- Generate learner text from typed facts only; never transclude source learner prose, glosses, morphlines, or evidence summaries.
- Pass the corpus path explicitly to the operational command; do not hardcode external workspace paths into repo files.
- Keep every candidate, report, payload, and verdict `live_mutation_allowed=false`.
- Do not alter the existing `fd-455-*` artifacts, external corpus, source whitelist, entries, or live/runtime surfaces.
- Use commit messages beginning with `fd2:` and do not push.
