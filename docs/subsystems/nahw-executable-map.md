There is deliberately **no** single generic naḥw resolver, and no rule's free-text `when` prose is executed: behaviour comes from a closed discriminator registry keyed by rule id plus the rule files' own structured fields. Consumption status is machine-enforced by `tools/validate_nahw_skill.py` (`RULES_CONSUMPTION`), where `consumed` requires a **distinct load-bearing on/off probe**: the production validator must fire on that file's own decision property AND stop firing when only that file's data is removed, while every other probe still fires (isolation). File existence, an import, a path reference, a self-reported status and a structural row check do **not** establish a consumer. Each helper's `FILE_CONSUMPTION` map must agree exactly with the authoritative inventory, so a helper can no longer call a fixture-gated row consumed. State-moving input must be a validated, immutable **observation artifact** (`typed_observation`): shape, authorized producer, canonical coordinate checked against the repository's own `tools/fusha_check.resolve_address` over the committed spine, binding to the exact token/surface/state/referent, and a content-integrity hash. An address-shaped string, a caller-minted producer, an impossible or newline-suffixed coordinate, a reused or surface-mismatched artifact and a mutated field all fail closed. Every candidate-producing consumer must also be told the caller's CURRENT exact address (`at=`): an internally valid same-surface artifact replayed at another occurrence is `occurrence_not_current`, and omitting the address is `caller_occurrence_absent` — never a candidate. Because no repository producer signs observations and the spine carries no per-word written surface, every registered producer is `fixture` trust and an artifact can yield at most `candidate` — packetized as `TP-NAHW-A2-OBSERVATION-PRODUCER`. A context sense is never authorized by `norm_strict` alone: trusted morphology (lemma, derived form, voice, POS) must confirm the lexeme, so Form II `يُقَدِّرُ` and passive `أُتِيَ` no longer inherit the Form I active tables. A registered reason key does not license an arbitrary conclusion: each key must satisfy a closed **licensing tuple** (conclusion, case/mood, governor type, fact type), with `fact_type` checked against the key's own `applicable_fact_types` in `qamus/skills/reason-key-registry.jsonl` and any key lacking repository tuple authority routed pending as `reason_tuple_unavailable`. So a fused-preposition genitive reason can no longer ride an accusative conclusion under a `verb_object` governor. A human/source review is bound to the exact claim it is offered for — same address, subject, conclusion and reason key, a canonical `hr:` identifier, an ISO-8601 timestamp and a reviewer distinct from the claimant — so a valid review of another address is not evidence here. LargeLexicon collision rows bind a typed `forbidden_reading_id`, so unrelated non-empty text can no longer stand in for a forbidden reading. Two-vote grading delegates the COMPLETE artifact contract (vote-id format, reviewer provenance, timestamp, occurrence, segmentation, lexical identity, root, form, conclusion shape, reason key) to `tools/validate_two_vote_artifacts.validate_vote()` before projecting for agreement, and layers engine/reviewer/lane/vote-id/worklist independence on top, requiring each `worklist_id` to be a valid non-empty canonical identifier BEFORE the two are compared (null, empty, whitespace and malformed ids are missing provenance, not different worklists); the worklist axis is an A2 addition, since the shared contract does not model worklists. A quarantine needs TYPED authority: a closed status vocabulary plus a packet **parsed as its structured artifact** carrying a machine-readable `QUARANTINE-BINDING` block (bank, status, exact row ids, uncovered property, permitted disposition). A fabricated file whose prose merely mentions the bank and row id has no `packet_id`, no binding block and no `NOT_DEPLOYED` record, so it authorises nothing. The only permitted disposition is `excuse_semantic_consumer`: gate strength and trigger/gate compatibility are checked for **every** row, quarantined or not, **before** any quarantine early return, so a quarantine can never hide a weakened gate. (Schema note: `qamus/schemas/task-packet.schema.json` is `additionalProperties: false` at every level and this lane may not widen it, so the typed binding lives inside the allowed `candidate_population.selection_rule` under a strict grammar.) Hover rows compare the consumer's exact decision, pending reason, reading and gloss against a committed binding — plus the bank's own `gloss_if_safe`, `safe`, `gate` and `key_fn`, so a wrong teaching gloss is caught even though no production consumer owns that axis (reported `bank_gloss_if_safe_axis: committed_binding_only_no_production_owner`) — and the bound/mutation counts are asserted so a neutered consumer cannot silently remove the adversarial axis; the production key-function selection lives in the rendering layer and is reported `key_selection: no_production_authority` rather than asserted. `run_nahw_evals.py --json` emits exactly one JSON document with a matching exit code. The grader validates reason keys against `qamus/skills/reason-key-registry.jsonl`, never certifies (agreement routes to `candidate_agreed_pending_certification`), requires a typed `expected_conclusion` compared exactly, treats `human_source_review_required` as a distinct gate needing its own validated independent review record (`two_vote_done` cannot substitute), and implements **no** candidate `nahw@2.1`–`@2.4` behaviour in the released path.

## 1. What the nahw subsystem is

Nahw is the syntax/context disambiguation layer after norm → ṣarf (`nahw/README.md:25-29,56-62`): particle function, governor/iʿrāb, referent, negation scope, homograph resolution by context. Skill text `nahw/SKILL.md` (489 lines): grammar-safety ANDON — "a correct answer with wrong iʿrāb reasoning is unsafe"; two independent checks must agree on **conclusion AND reason** (`nahw/SKILL.md:12-19`); 25-link procedure index (`:21-46`); output contract JSON with `function_class`, `attachment`, `composition`, `parse_key`, `display.segments`, `decision`, `allowed_for_hover` (`:87-105`); governor/dependency-lattice section (`:275-314`); six nahw principles (`:318-326`).

Released tier is naḥw@2. Four CANDIDATE increments are appended, each stating "NOT released; does not amend @2": @2.1 8 rules (`nahw/SKILL.md:374-406`), @2.2 3 rules (`:408-427`), @2.3 2 rules (`:429-448`), @2.4 4 rules (`:450-488`). Machine rows live in `qamus/skills/rule-registry-increment-2N.jsonl` with discriminators `tools/skill_fixtures/skill_rules_increment2N.py`. All 17 nahw increment rows are `status: candidate` (GAP-N1). The registry row schema — where `status`, `projector.guards`, `defeaters`, `abstention_condition` actually live — is uniform with the sarf registry (see `docs/subsystems/sarf-executable-map.md` §2); `mood_basis` is a two-vote-artifact field, not a registry field.
