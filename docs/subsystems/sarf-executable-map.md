**Coverage is claimed per PROPERTY, not per bank.** Each behavioural bank declares `property_coverage`: the property key, the callable that decides it, the number of applicable rows and whether it counts as coverage. The runner counts, per property, how many rows it was actually evaluated on and fails if that differs from the declaration or if an undeclared property is evaluated. A property decided `structural:<module>` (a normalizer or shape assertion) may never be marked covered. Every hit is recorded by the exact DECLARED CALLABLE and the row id, so relabelling a property's `decided_by` to a callable that never produced the asserted value fails, and a zero-row, duplicate, undeclared or counterless property can never raise coverage. Current totals: **26 covered properties, 4 uncovered** — the two normalizer properties of the byte-exact bank (`marks_transparent_to_matching`, `cluster_alignment`), the clitic bank's `tanwin_alef_guard` cross-check, and the lattice bank's `evidence_class_agreement`, which disagrees with the engine on exactly `MCL-002` and `MCL-005` (reported per row, packetized to `TP-SARF-A1-LATTICE-EVIDENCE-CLASS`, and never raised into a released rule).

**Candidate/projector/public boundary.** The candidate check cross-joins the `@2.1`–`@2.4` rule ids against the declared surfaces (`candidate_boundary_surfaces`: the projector registry, the certification stores and the skill registries — 1,000+ records, a minimum the contract pins) and fails on any record that cites a candidate rule while declaring a certified/released state, a public-materialization allowance or a public/live target. Candidate linkage established by any ancestor is INHERITED by every descendant object and array element, so a parent `rule_id` with a nested certified state cannot hide. Every path-bearing contract field — bank paths, Store A paths, candidate record roots, the projector surface and every `registry_files` entry — is contained before any I/O: no `..`, no absolute or drive path, no URL, no backslash, and the real (symlink-resolved) target must stay inside the worktree. Diagnosis is not enforcement, so two independent mechanisms apply: `run_all` **aborts before any contract-directed loading** when validation fails (no bank read, no Store A proving, no boundary scan, boundary rendered `not_checked`), and every loader converts a declared path through `guarded_abs()`, which raises `PathContainmentError` before `exists`, `isdir`, `listdir`, `walk`, `glob` or `open` can see the target. The bank-existence probe in `validate_contract` itself is likewise only performed after containment passes. It is read-only and promotes nothing. A targeted `--bank` run does **not** execute it and renders `candidate/projector/public boundary: not_checked` rather than claiming verification.

**Contract validation executes its schema.** `validate_contract` now runs the committed JSON Schema (a bounded draft-2020-12 subset executor, stdlib only) before the semantic checks, so `additionalProperties: false`, required keys and value shapes are enforced rather than merely declared; it also rejects duplicate bank/rule entries and any path that is absolute, climbs out of the repository or leaves `sarf/evals/` / `sarf/rules/`. The executor fails closed on a schema keyword it does not implement. Schema and semantic validation are additive; neither substitutes for the other.

**Coverage arithmetic.** 4 banks / 142 rows are behaviourally decided (`false-clitic-split`, `morphology-candidate-lattice`, `largelexicon-collision-safety`, `combining-mark-byte-exact`); 6 banks / 248 rows are `candidate_no_consumer` and 1 bank / 2 rows is `documentary`. `decided_rows` is returned by each adapter and never assumed from the row count, so a structural adapter reports 0. `--strict` and `--strict-sarf` are **disposition-completeness** gates (every bank labelled and packetized); neither is a behavioural-coverage claim.
