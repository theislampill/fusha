`impl-records/VNREC-RECONCILIATION-2026-07-17.md` and by the VN readiness v2 program

in any surveyed workspace. They were either never persisted or already lost. Only the
reconciliation `.md` (private custody) survives.

committed repo inputs only, so the dangling citations resolve to an honest artifact instead
of a 404:

- `vnrec-authoritative-membership.reconstruction.json` — the VN-00/01/02 CLOSED-FROZEN
  window contracts (92 source keys each, expanded from
  `build_vn_readiness_v2.py::FROZEN_SCOPE_TEXT`) plus the VN-03→VN-23 planning-baseline
  windows (`PLAN_WINDOWS`), joined against the 2,092 committed entry source keys.
  The original's **staging namespace is NOT reconstructible** (the vn00 rollout staging
  snapshots are server-side inputs); it is recorded as `staging_metadata.available: false`.
- `vnrec-conflicts.partial-reconstruction.jsonl` (+ `.meta.json`) — **PARTIAL**: the
  claim-divergence rows still preserved in `vn-ledger.jsonl` (every ledger row carries
  `vn_tranche = null` with a preserved balanced-partition `proposal_vn_tranche` claim that
  diverges from the documented/plan window). The **original 164 staging-history dual-claim
  rows are unrecoverable from repo data** (`recovered_row_count: 0` in the meta) because
  they depended on the rollout staging snapshots.
