# Reference — nisba (ـيّ) vs abstract-noun (ـيّة) suffix classification

| Function | Final letter | Shadda-on-yaa evidence | Base-category evidence |
|---|---|---|---|
| nisba_relational_yaa | none_word_final_yaa | written_shadda | nisba_relational_attested |
| abstract_noun_yaa | taa_marbuta | written_shadda | (not required) |
| non_nisba_geminated_yaa_adjective | none_word_final_yaa | written_shadda | non_nisba_adjective_attested |

ـيّ (nisba/relational, مِصْرِيّ "Egyptian") and ـيّة (abstract noun,
إِنْسَانِيّة "humanity") are DISTINCT classifiers; both share a geminated
yaa, so the shadda itself must be written evidence, never assumed. A
`candidate_pending` function label is a SUFFIX CLASSIFICATION only — it
never infers the base lexeme's identity or a contextual sense. An unmarked
(unvocalised) surface carries no shadda evidence and abstains
`insufficient_features` — normalisation is never treated as confirmation.

**The nisba shape also collides with a non-nisba rival.** A word-final
geminated yaa with no trailing taa marbuta (`none_word_final_yaa` +
`written_shadda`) is ALSO the exact shape of a closed set of non-nisba
faʿīl-pattern adjectives — قَوِيّ "strong" is a near-collision, not a
nisba or an abstract noun. Shape and written shadda alone never decide
this rival: `nisba_relational_yaa` additionally requires
`base_category_evidence: nisba_relational_attested`, and the distinct
`non_nisba_geminated_yaa_adjective` function requires
`base_category_evidence: non_nisba_adjective_attested`. Without a declared
base-category evidence value the row abstains `insufficient_features`
rather than defaulting to nisba from shape alone.
